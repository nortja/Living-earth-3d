# 0.18.1 candidate validation

Prepared 2026-10-31. Removes the redundant Search heading and puts previous/next paging in one row so the first offline result is fully visible at small sizes. A new native assertion reproduced one failure on the prior layout, then passed after repair; first and middle pages render at seven sizes through 5K. No new provider requests or saved-data changes occur.

Recording contexts now use the screen index from the existing one-second report poll rather than enumerating Windows monitors every frame. Quality/cap/viewport/scale/window-mode fields remain per-frame; the exported report explicitly states the approximate one-active-second screen-index latency. Godot 4.6.3 Windows source shows current_screen calling MonitorFromWindow and EnumDisplayMonitors; see https://github.com/godotengine/godot/blob/4.6.3-stable/platform/windows/display_server_windows.cpp . This avoids a platform-specific per-frame API query; actual Windows timing/API-cost evidence follows fresh gates and is not assumed from Linux results.

The release adds the strict actual Windows 1080p/ultrawide/4K/5K framebuffer matrix to its installed desktop gate, using the independently exercised optional post-start resize on the small CI desktop. Full native dimensions remain mandatory; physical monitor/DPI claims remain separate. The maintainer display harness supports PowerShell5.1/Core. A bounded native monitor-query probe reports API cost without a frame-rate threshold or hardware claim.

Final native performance layouts and first/middle-page atlas checks pass; screenshots reviewed.
