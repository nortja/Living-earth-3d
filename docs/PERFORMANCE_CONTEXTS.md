# Recording display configuration changes

Settings → Performance & support → Record 5 active minutes keeps the existing local recording. Exporting its JSON now adds `recording.contexts`: consecutive active frames grouped by quality, actual FPS cap, viewport pixels, interface scale, active screen index and window mode. Each segment has its start offset in active seconds, duration, frame count, mean/max frame interval and frames above 50 ms. The overall totals remain available. Frame intervals include the cap/scheduling; they are not raw GPU render timings.

This makes a recording interpretable when moving/resizing a window or switching 2K/4K and 30/60 FPS. A 30 FPS segment is not silently described using the final 60 FPS setting. The monitor index comes from the latest display-report poll, normally up to one active second old; the other configuration fields are sampled each frame. This avoids enumerating Windows monitors for every rendered frame. The monitor inventory remains a current snapshot, not a historical DPI/refresh trace. No hardware score or physical validation claim is inferred.

Memory stays bounded: after 31 configuration segments, all remaining frames use one explicitly mixed bucket, without a false configuration claim. Every frame/active second remains accounted for; a new recording resets the history. Returned/exported dictionaries are independent copies. Minimized, native/in-app screensaver and sleep-sized gaps remain excluded. Native savers do not collect these desktop samples.

The schema-1 report keeps its prior fields and adds optional context fields. It includes no usernames, file paths, bookmarks, camera images or account/device location, and uploads nothing. Engine-tracked memory is unavailable in release builds and remains null; it is not process/GPU memory.
